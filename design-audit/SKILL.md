# 设计审计

> **环境里有更具体的设计流程与审计指引时，以它为准，不要两套同时走。** 例如宿主应用随包带了自己的 `design.md`（会话开头的能力说明会指向它，里面有按宿主定制的候选来源、确认方式和运行脚本的办法）：你被调用时发现了这样的指引，就直接去读它、按它做，本 skill 的其余内容只当背景参考。两套流程同时走，会各问一遍、各写一份，互相打架。

用项目自己的设计令牌当尺子，扫出界面代码里偏离它的地方；再加一组不需要令牌也成立的通用界面规则。**只读**：脚本不改任何文件，改动由你按用户确认后做。

## 它做什么，不做什么

- 做：静态扫描 `.css .scss .less .html .vue .svelte .jsx .tsx .js .ts`，查 17 条规则（见 `references/rules.md`）：写死的颜色 / 字号 / 圆角 / 间距 / z-index / 动效时长 / 阴影、去掉焦点环、禁止缩放、图片缺 alt、非语义元素上的点击、`transition: all`、过小字号、半像素、减弱动效缺失。
- 做：基线模式——把现状记下来，之后只许减、不许增，当「守卫」接进项目的检查命令。
- 不做：真实浏览器里的计算样式、对比度实测、读屏与键盘顺序。那些需要运行时工具（例如 axe、AccessLint），本 skill 没接。**每次报告都要写清没覆盖什么。**
- 需要 Node 18 及以上（在 Node 26 上测过）。零依赖、不联网。

## 流程

1. **确定范围（能推断就不问）**：用户指了目录或文件就用它；没指就默认当前项目的源码目录。找令牌文件：先看 `design-system/tokens.css`、`docs/design-system/tokens.css`，也可以用 `--tokens` 指定。
   - **找到令牌**：按它审。
   - **没找到令牌**：告诉用户「没有设计系统，只能做通用规则」，摆一张选择卡（一次一问）：先用 `design-system-first` 立一套 / 只做通用规则。别硬审。
2. **跑脚本**：
   ```bash
   node <skill 目录>/scripts/audit.mjs <目录> [--tokens design-system/tokens.css] --format json
   ```
   退出码：0 通过；1 有「错误」级问题；2 用法有误。想看人读的版本去掉 `--format json`。
3. **解读，别把几百行原样丢给用户**：
   - 先说结论一句：错误几个、建议几个、提示几个，最大的一类是什么。
   - 按「错误 → 建议（按数量从多到少）→ 提示」归纳，每类给 2–3 个 `文件:行号` 例子、影响面、修法。
   - 把建议分成两种：**等于令牌的字面值**（脚本写着「等于 --xxx，请用 var(--xxx)」，机械替换、没有风险）和**不在阶梯里的值**（需要决定：并到最近的档，还是登记例外）。
   - 令牌里有但字面值没对上的，说明是「令牌缺这一档」还是「页面写偏了」，别替用户决定。
4. **问用户下一步（一次一问，选择卡，带推荐）**：
   | 选项 | 推荐 |
   | --- | --- |
   | 先修错误级问题（焦点环、alt、缩放）| 推荐，影响真实用户 |
   | 机械替换「等于令牌」的字面值 | 安全，批量 |
   | 把现状记为基线，只防新增 | 项目很旧、一次改不完时 |
   | 登记例外 | 有意为之的写死值 |
5. **改之前再确认**：用一张确认卡复述范围——要改几个文件、几处、哪类规则——点了才动手。用编辑工具改，不要用脚本批量改（脚本只读）。
6. **复审**：改完重跑，报告前后对比（例如「错误 14 → 0，建议 515 → 380」）。没降下来的原样说，不粉饰。

## 守卫（基线只减不增）

```bash
# 第一次：把现状记为基线（之后只许减）
node <skill 目录>/scripts/audit.mjs . --baseline design-system/.audit-baseline.json --update-baseline
# 之后每次检查：比基线多了就退出码 1
node <skill 目录>/scripts/audit.mjs . --baseline design-system/.audit-baseline.json
# 修掉一批之后：把基线压到当前水平（有任何一项比基线多会被拒绝，除非明确加 --allow-raise）
node <skill 目录>/scripts/audit.mjs . --baseline design-system/.audit-baseline.json --update-baseline
```

**先把 `audit.mjs` 拷进项目**（单文件、零依赖，例如 `scripts/design-audit.mjs`），上面命令里的脚本路径就换成它，这样守卫跑在项目自己的检查命令或 CI 里，不依赖外部安装位置。把第二条接进检查命令。基线按「文件 × 规则」记数量，所以旧文件里的老问题不挡路，新文件和新增的问题会被拦下。

## 例外登记

有意写死的值，在问题所在行或上一行写 `ds-ignore: 理由`（注释形式随语言：`/* */`、`//`、`<!-- -->`）。**理由必填**：不写理由的不算登记，反而多一条 `meta/ignore-no-reason`。所有登记过的例外会列在汇总里，方便定期复查。

## 局限（报告里要说）

- **静态行扫描，不解析 AST**：多行的 JSX 属性、动态拼出来的样式、`styled-components` 模板字符串里的样式不查。
- **只认写死的 hex / `rgb()` / `hsl()` / `oklch()` 颜色**；`red`、`white` 这类颜色名不查。
- **看不到计算样式**：层叠、继承、媒体查询最终生效的值，这里不知道。
- **令牌名要能认出来**：识别 `--fs-* / --radius-* / --space-* / --dur-* / --z-* / --shadow-* / --color-*`（及 `--text-`、`--rounded-`、`--sp-`、`--duration-`、`--elevation-` 等别名）。认不出的类别脚本会在「说明」里写明并跳过。
- **误报用 `ds-ignore` 登记**，不要为了让它变绿去改规则或删检查。
- 默认跳过 `node_modules`、构建产物、测试文件、令牌文件所在目录；要审测试文件加 `--include-tests`。

## 输出要求

- 先结论，再分类，再下一步；`文件:行号` 用代码格式。
- 汇报数字照抄脚本，不估算。
- 完成时报告：审了哪些目录、用了哪份令牌、**没覆盖什么**（运行时对比度、读屏、键盘顺序、颜色名、模板字符串里的样式）。
