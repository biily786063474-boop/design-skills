# UI 规划先做设计系统

**为什么**：界面各页不一致，几乎从来不是谁做错了，而是开工时没有先定标准，每个页面各自定了一份——于是字号几十种、圆角几十种、同一种抽屉每页边距不同、z-index 和阴影各写各的。事后统一要审计、拍板、迁移、对照验证，成本远高于一开始就定。所以：规划 UI 时先做这份设计系统，粒度要细，按项目灵活取舍。（一个真实的事后补救案例见 `references/case-study.md`，需要量级感时再读。）

## 何时触发

- 新项目 / 新应用 / 新产品线的 UI 规划（写任何页面之前）
- 改版、重新设计、新增一整块界面（不是单个小控件）
- 用户抱怨「各页面不一致」「哪里都差一点」（走 §已有项目）
- **不用**：改一个按钮的颜色、修一个具体 bug、一次性海报 / 封面（对外物料按平台惯例，不套本流程）

## 第 0 步：定档（一句话告诉用户选了哪档、为什么）

| 档 | 适用 | 必做维度 | 不做 |
|---|---|---|---|
| **轻** | 营销站、落地页、一次性原型、活动页 | 颜色（表面 / 文字 / 强调 / 语义）、字阶 + 字重 + 行高、圆角、间距阶梯、阴影、动效时长 + 缓动、断点 | 守卫、迁移工具、状态矩阵 |
| **标准** | SaaS / 后台 / 多页面产品、有 2 人以上改 UI | 轻档全部 + 控件高度、z-index 层级、焦点环、透明度状态、图标尺寸、**组件状态矩阵**、**页面版式模板**、暗亮两套（如需要）、**字面值守卫** | 迁移工具、探针、规范页 |
| **完整** | 桌面应用、长期维护、多人 / 多 agent 并行改 UI | 标准档全部 + 信息分级暴露、说明文字规范、无障碍对比度、减弱动效、例外登记、迁移工具、**前后对照探针**、规范页、版本号与变更记录、多语言长度规则 | — |

拿不准选**标准**。**不许跳过本步直接画页面**；确实只要「轻」也要说出来，让用户知道哪些维度被有意省略。

维度清单与每档要求见 `references/dimensions.md`；推导脚本与规则见 `scripts/derive.mjs`、`references/derivation.md`；手写令牌骨架见 `references/tokens-template.css`（用脚本推导时不需要）。

## 流程（新项目）：逐步确认，由规则推导

核心思路：**少问多推**。只问会改变整套结果的 5 件事，其余几十个值由脚本按规则推导，最后把推导结果摊开给用户看，用户只改他想改的。主流程只有 6 张确认卡；用户选「全按推荐」时只剩 3 张。

1. **读项目（不问）**：平台、已有样式与令牌、语言、明暗、团队规模，读到的写成「假设」。项目里已经有大量字面值却没有令牌 → 转下面的「已有项目」流程。
2. **Q1 画像**（表单卡）：默认值就是上一步的假设。
3. **Q2 定档**（选择卡）：轻 / 标准 / 完整，带推荐。
4. **Q3 气质**（选择卡）：2–3 个候选，每个先跑出预览页给用户看，再让他选；用户可以直接给品牌色。
5. **Q4 密度**（选择卡）：紧凑 / 标准 / 舒展，选项里写出实际的字号和控件高度。
6. **Q5 形状与动效**（选择卡）：锐利利落 / 适中克制 / 圆润柔和。
7. **推导**：`scripts/derive.mjs` 一次算出全部维度（字阶、间距、控件高度、圆角、颜色、阴影、动效、层级、状态矩阵、页面版式），并自动校验；任何一项不达标就报错，不继续。
8. **Q6 终确认**（确认卡 + 预览页）：每个值旁标出处，「声明的假设」单独列出；用户要改单个值就写进例外登记（必须写理由），重新推导再确认。
9. **落盘并接守卫**：`design-system/` 下生成 `tokens.json`（DTCG 三层）、`tokens.css`、`DESIGN-SYSTEM.md`、`DECISIONS.md`；标准档起把「新文件字面值为零、旧文件只减不增」接进项目的检查命令——用 `design-audit` 的基线模式（`audit.mjs --baseline … --update-baseline`），它就是守卫。
10. **验收用探针量真实值，不读 CSS**：量相邻元素的真实空隙、真实计算样式，多语言 × 暗亮各一遍；有数据 / 空状态都要开。详见 §验收。

**铁律**：一次一张卡，摆卡后直接结束这一轮；每个选项带推荐理由；每张卡的回应立即追加到 `DECISIONS.md`，对话中断后从那里恢复；没问过的维度不装作问过。卡片脚本、推荐规则、恢复与降级见 `references/flow.md`；推导规则与校验清单见 `references/derivation.md`；气质候选见 `references/moods.md`。

**档位决定做多少**：轻档的输出没有控件高度、层级、焦点环、状态矩阵和守卫；完整档多无障碍对比度表、多语言长度、变更记录。

**档位少而有间隔**：字阶 7 档（整数 px）、圆角 6 档加胶囊、控件高度 3 档、间距 2px 栅格，相邻档要看得出差别；半像素一律不进阶梯，间距、圆角、控件高度取偶数。

## 已有项目：审计 → 决策码 → 迁移 → 守卫

1. **审计**：全仓样式静态扫描，按功能区归并（字号 / 字重 / 圆角 / 内边距 / 高度 / 颜色），再用运行中的界面量计算样式。产出：每个维度「有几种写法、各多少条、在哪些功能区」。**数字出口径前先核对口径**（例如：别把登记的例外文件算进违规）。
2. **汇报页 + 决策码**：给用户看可视化对照，每个取舍给一个默认值，让用户复制一行决策码回来（例：`字阶=A · 范围=B · 例外=A`）。
3. **迁移**：用 AST 工具做批量改写（只改声明值，格式不动），先试跑只报数，按维度分批；平局规则写死（半像素向上、14→12 向小）。
4. **守卫**：进项目的本地检查 / CI，按文件基线只减不增。
5. **对照验证**：同一脚本前后各跑一遍，逐界面比像素与计算样式，肉眼看截断 / 溢出。

做过一遍的完整做法、脚本形态和踩过的坑见 `references/case-study.md`。

## 验收（容易假通过的地方）

- **脚本点得太早**：打开视图后必须等它真的渲染出来再量，否则量到的是空界面。**每个界面截图后看一眼是不是想要的界面。**
- **参数静默失效**：多组数据（语言 × 主题等）靠命令行参数切换时，参数没传进去会静默回落默认，两组数据其实一模一样。**两组数据完全一致时先怀疑参数没传进去。**
- **空状态不等于验过**：有数据的状态要再量一遍；没验就写「未验证」。
- **量真实空隙**：margin、gap、伪元素叠出来的才是用户看到的；只读样式里写的单个值会漏。
- **多语言 × 亮暗组合**：长语言会换行；亮色下对比度和阴影表现不同。
- **前后对照的「前」要是真基线**：同一份脚本、隔离环境、别抢用户正在用的窗口。

## 输出要求

- 开始规划时：先给「定档 + 维度清单（哪些做、哪些有意省略）」，让用户确认或改档。
- 令牌与规范落成项目内文件（令牌文件 + 规范文档；给人看的汇报页做成本地 HTML）。
- 完成时报告：每个维度立了什么、守卫是否到位、**没覆盖什么**。

## 反模式

- 先画页面，再「回头统一」。
- 把配色表当成完整设计系统。
- 阶梯里放半像素、奇数 px、间隔不足 2px 的相邻档。
- 只立尺寸不立状态（disabled 是多少透明度、focus 长什么样，没人知道）。
- 只立标准不立守卫——一个月后又长回 30 种字号。
- 例外不登记：「这个页面特殊」没写理由，守卫就只能放行或误杀。
